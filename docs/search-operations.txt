索引の仕様
scripts/build_search.py が公開台帳とブログ台帳だけを読んで生成します。
canonical・確定301を統合し、下書き・非公開・archive・noindex・機能ページを除外します。
検索用NFKC・かな統一は検索キーだけです。表示と原文を書き換えません。
説明・見出し・キーワード・本文をAND検索します。1文字は題名・ID・確認済みentityに限定します。
本文は128分割のbigram索引で候補を絞り、原文由来の全文で連続一致を確認します。
頻度ヒントは候補の読込み順のためだけで、検索の正解を変更しません。
最大20MBのworker内キャッシュ、本文の同時読込み6件、各取得15秒のtimeoutです。
空検索は全件、新しい順に20件ずつ。未確認の日付は末尾になります。
明示的な「・更新」新着台帳の更新日も使い、c056の2026-10-04訂正を新しい順へ反映します。
manifestは最後に切替えます。生成済みの古いデータだけを削除し、非公開化した本文を古い索引に残しません。
古いタブで取得に失敗した場合は0件にせず、再試行で最新manifestを取得します。
metadata/本文/gramはhash付き、manifestはno-store。FunctionsでもこのHTTPヘッダーを設定します。

索引失敗
npm run buildで再生成し、search:checkとguardを通します。manifestだけを手で更新しません。
画面の「もう一度試す」と、全記事一覧・20件ずつの通常リンクは失敗時にも利用できます。
D1の掲示板や反応データは検索データへ取り込みません。
検索ページには解析scriptを追加せず、旧/?q経由も解析を抑止します。
検索ページから出る参照元はoriginだけです。検索語はsessionStorage/URLに保存する必要範囲に限定します。
サーバーのアクセスログ等にはURLのqueryが残り得ます。providerログの保存期間・閲覧権限は運営者確認が残っています。
